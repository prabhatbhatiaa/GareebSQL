ACID Guarantees Under the Hood

How MySQL 8.0 protects every rupee during this transfer.

TCL + CHECK CONSTRAINTS
A
Atomicity (All or Nothing)

Debit, credit, Transfer_Out, and Transfer_In execute inside one transaction block. Any failure triggers ROLLBACK.

C
Consistency (Domain Rules)

Enforced via CHECK (balance >= 0), CHECK (amount > 0), and active account status checks before updating.

I
Isolation (Row-Level Locks)

SELECT ... FOR UPDATE prevents concurrent double-spending race conditions on the sender's balance.

D
Durability (InnoDB Redo Log)

Once COMMIT returns, updated balances and ledger entries persist permanently in MySQL.

LAYER 01 · SCHEMA

BCNF Normalized Model

6 tables (branches, customers, accounts, transactions, loans, loan_payments) decomposed from UNF → 1NF → 2NF → 3NF → BCNF with strict PK, FK, UNIQUE, and CHECK constraints.

→
LAYER 02 · ENGINE

MySQL 8.0 Core

Executes composite indexes (idx_txn_account_date), read-only views, DCL privilege roles (bank_teller, auditor_readonly), window functions, CTEs, and ACID transactions.

→
LAYER 03 · BRIDGE

FastAPI Raw SQL API

Lightweight Python REST bridge running parameterized raw SQL queries without ORM abstraction so every query remains transparent and auditable.

→
LAYER 04 · CLIENT

Interactive Ledger UI

Zero-dependency HTML/CSS/JS frontend with live theme switching, real-time running statements, and atomic transfer testing.
